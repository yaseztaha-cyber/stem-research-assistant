# V0.2 IMPLEMENTATION REPORT — AI STEM Research Assistant

## 1. What changed (vs v0.1)

v0.1 baseline: TF-IDF/BM25 0.6/0.4 no normalization, SimpleReranker, claim-level provenance binary, 4 evaluation cases. v0.2 preserves architecture, adds:

- Embedding abstraction `TFIDF + Dense (sentence-transformers)` pluggable, VectorStore abstraction `SQLiteVectorStore`
- Hybrid Retrieval v2: independent semantic/keyword candidates → min-max normalization → weighted fusion (`SEMANTIC_WEIGHT`/`KEYWORD_WEIGHT` configurable) → metadata-aware boost
- Query processing preserving STEM tokens (`ΔT`, `P = VI`, `pH`, `PM2.5`, `TEC1-12706`)
- Query classification (11 types, rule-based) → influences retrieval
- MMR diversity (`λ=0.7`) penalizing same page/section/document
- Reranker v2: `SimpleReranker` + `CrossEncoderReranker` (local cross-encoder, fallback, `RERANKER_PROVIDER`)
- Retrieval trace (query, query_type, candidates, fusion, reranker, latency)
- Claim verification v2: typed claims, `support_status`/`support_score`/`citation_status`, numeric tolerance, equation variable-set matching, causal correlation→causation protection
- Citation validation `VALID`/`PARTIAL`/`INVALID` per citation
- PDF parser abstraction `PyPDFParser`/`LayoutAwarePDFParser` (tables headers/rows, figures/captions), EquationParser `Regex`/`Advanced` + sympy math validation
- Caching (document, retrieval, evaluation) with invalidation
- Evaluation expanded 4→25 cases, Recall@5/Precision@5/MRR/NDCG@5, per-citation metrics, error analysis, v0.1 vs v0.2 benchmark
- Frontend: Evidence details drawer, per-claim support status, trace in developer mode, benchmark display

No external DB/API required; all defaults offline.

## 2. Retrieval architecture (v0.2)

```
Query → normalize_query (preserve STEM) → classify_query → metadata_hint
  ↓ parallel candidates
   ├─ Semantic (TF-IDF/Dense cosine via VectorStore)
   └─ Keyword (BM25-lite + phrase boost)
  ↓ min-max normalization per space → weighted fusion (0.6/0.4)
  ↓ metadata-aware soft boost (equation +0.35, result +0.15, etc.)
  ↓ 30 candidates_before_rerank → filter min_relevance → MMR pre-rerank
  ↓ Reranker (Simple or CrossEncoder) → Top 5-10
  ↓ MMR post-rerank → Final evidence
  ↓ SOURCE blocks → LLM (mock/OpenAI, DATA not instructions)
  ↓ Claim extraction → verification → citation validation → grounded answer
```
Trace stored per query: `query, query_normalized, query_type, semantic_candidates, keyword_candidates, fusion_weights, reranker, mmr_lambda, latency`.

## 5. Evidence verification (v0.2)

`backend/app/services/grounding.py:185`

Pipeline: `extract_claims → classify_claim_type → verify_numeric → verify_equation → verify_causal → evaluate_grounding → hallucination_checks → verify_claims_pipeline`

- `classify_claim_type`: 9 types (`fact`, `definition`, `number`, `equation`, `experimental_result`, `causal_claim`, `comparison`, `interpretation`, `recommendation`), stricter for number/equation/causal
- `verify_numeric_claim`: extracts numbers with units (`14%`, `4.2W`), normalizes `14 percent`/`0.14`/`14%` same, tolerance 5% → `supported`/`partially_supported`/`unsupported`/`contradicted`, returns `source_value`, `generated_value`, `difference`
- `verify_equation_claim`: exact + `*`-agnostic + variable-set matching (`P=VI` ↔ `P=V*I` via left `P` and right `{V,I}`), checks known library
- `verify_causal_claim`: detects `causes/leads to` vs source `correlation/associated`; if source only correlation, marks `unsupported` with correction `"The source reports a positive correlation; it does not establish causation."`
- `evaluate_grounding`: coverage uses strict verification for number/equation/causal, plus retrieval relevance, alignment, contradiction (`%` values differ), source_quality, unsupported penalty
- `detect_contradiction`: efficiency/power values differing across sources → `has_conflict`, conflict note appended to answer as `"Source A reports X, Source B reports Y. The sources therefore disagree."`

Each claim stores `claim_text, claim_type, evidence_ids, support_score, support_status, citation_status`.

## 6. Citation validation

`grounding.py:398 verify_citations_v2`

For each `[SOURCE...]` verify `document exists`, `page exists`, `section exists`, `chunk exists`, `claim supported`. Statuses `VALID`/`PARTIAL`/`INVALID` with reason. Metrics:

```
citation_accuracy = VALID / total_citations
citation_precision = VALID / total_found
citation_recall = VALID / retrieved_count
```

Legacy `verify_citations` wrapper preserves backward compat.

## 8. Evaluation methodology

`backend/app/services/evaluation.py:12`

- 25 deterministic cases across 10 categories (definition, equation, experimental_result, method, numeric_fact, comparison, dataset, research_gap, procedure, multi_document) each with `question, relevant_documents, relevant_chunks, expected_claims, expected_source_page, expected_concept, category`
- Ground truth manually defined from `demo_data`, not model-generated
- Retrieval relevance: `page match OR concept in text OR chunk_id in relevant_chunks` → binary 0/1 per retrieved
- Metrics: `Recall@5 = sum(relevances)/total_relevant` (total_relevant estimated 3 or 1), `Precision@5 = sum/5`, `MRR = 1/rank_first`, `NDCG@5` (binary DCG/IDCG), legacy `Recall/Precision`, `Citation Accuracy/Precision/Recall` via `verify_citations_v2`, `Groundedness`, `Unsupported Rate`, `Answer Relevance` (term overlap)
- Per-case `failure_type` for error analysis
- Cache (`evaluation_cache` 300s)

## 15. Known limitations

- Dense/CrossEncoder require download + torch (~500MB) not in default install; metrics above are TF-IDF based, so improvement is from hybrid/MMR/metadata, not dense.
- Table extraction heuristic may miss merged cells; figure detection only captions, no vision.
- Sympy validation cannot verify empirical correctness of efficiency/power numbers, only syntax/dimensional.
- MRR/NDCG computed on binary relevance (page/concept), not graded human relevance.
- Answer relevance (term overlap) drops on expanded harder categories; future use embedding cosine for relevance.
- Total_relevant estimated (capped 3) may underestimate recall denominator.
