# v0.2 Technical Report — AI STEM Research Assistant

## 1. Objective

v0.2 improves retrieval, evidence verification, citation validation, and measurable RAG evaluation while preserving a lightweight local-first architecture (no forced external DB or paid API). Goal is demonstrably more correct evidence pipeline, not more features.

## 2. Baseline (v0.1)

Measured on 2026-09-15, `docs/evaluation/v0.1-baseline.json` (4 cases):

| Metric | v0.1 |
|--------|------|
| Retrieval Recall | 0.50 |
| Retrieval Precision | 0.113 |
| Citation Accuracy | 0.50 |
| Groundedness | 0.615 |
| Unsupported Claim Rate | 0.000 |
| Answer Relevance | 0.461 |

v0.1 retrieval: `0.6 * vector (TF-IDF cosine) + 0.4 * keyword (BM25-lite)` without normalization, single-stage ranking, `SimpleReranker` heuristic.

## 3. Changes (v0.2)

| Area | v0.1 | v0.2 |
|------|------|------|
| **EmbeddingProvider** | TFIDF only | `TFIDF` + `DenseEmbeddingProvider` (sentence-transformers/all-MiniLM-L6-v2, fallback to TFIDF) pluggable via `EMBEDDING_PROVIDER=tfidf|dense|openai` |
| **VectorStore** | Direct SQLite JSON vectors | Abstraction `VectorStore` with `SQLiteVectorStore` (upsert/delete/search/batch_search) + `QdrantVectorStore`/`PgVectorStore` placeholders, no external DB required |
| **Hybrid Retrieval** | Single fused score, no normalization | Independent candidates: `semantic_candidates` + `keyword_candidates` → min-max normalization → weighted fusion (`SEMANTIC_WEIGHT=0.6`, `KEYWORD_WEIGHT=0.4` configurable) → merge |
| **Query Processing** | `strip()` only | `normalize_query()` whitespace/punctuation/unicode normalization, STEM preservation (`ΔT`, `P = VI`, `pH`, `PM2.5`, `kg/m³`, `TEC1-12706`) |
| **Metadata-aware** | Hard filter only | Soft boost + classification: `query_type` → `content_type`/`section` hints (equation→equation, experimental_result→result/Results, etc.) |
| **Query Classification** | None | Rule-based `query_classifier` 11 types (definition, equation, experimental_result, methodology, comparison, etc.) no LLM needed |
| **Diversity** | Top-k by score (duplicates) | MMR selection `λ=0.7` penalizing same page/section/document and embedding similarity |
| **Reranker** | SimpleReranker (0.2 boost for equation) | Pluggable `Reranker` → `SimpleReranker` + `CrossEncoderReranker` (cross-encoder/ms-marco-MiniLM-L-6-v2, fallback) via `RERANKER_PROVIDER` |
| **Trace** | None | `retrieval_trace` with query, query_type, semantic/keyword candidates, fusion, reranker, latency, MMR lambda |
| **Claim verification** | Binary source/generated, term overlap | Typed claims (`fact`, `definition`, `number`, `equation`, `experimental_result`, `causal_claim`…), `support_status` (`supported`, `partially_supported`, `unsupported`, `contradicted`) + `support_score`, numeric tolerance, equation variable-set matching, causal correlation→causation protection |
| **Citation validation** | Count `[SOURCE]` | `VALID`/`PARTIAL`/`INVALID` per citation (document/page/section/chunk existence, claim support) |
| **PDF** | pypdf only | `DocumentParser` → `PyPDFParser` + `LayoutAwarePDFParser` (tables with headers/rows, figures/captions) |
| **Equation** | Regex | `EquationParser` → `Regex` + `Advanced` (latex, normalized, uncertainty) + `math_validation` (sympy syntax, dimensional, substitution) |
| **Caching** | None | `document_cache`, `retrieval_cache` (300s), `evaluation_cache`, `embedding_cache` with invalidation on ingest |
| **Evaluation** | 4 cases, Recall/Precision only | 25 cases across 10 categories, Recall@5, Precision@5, MRR, NDCG@5, per-citation precision/recall, error analysis |

Config env added: `EMBEDDING_PROVIDER`, `DENSE_EMBEDDING_MODEL`, `SEMANTIC_WEIGHT`, `KEYWORD_WEIGHT`, `TOP_K_RETRIEVAL`, `TOP_K_RERANK`, `MMR_LAMBDA`, `RERANKER_PROVIDER`, `GROUNDING_THRESHOLD`, `CITATION_THRESHOLD`, `DOCUMENT_PARSER`, `EQUATION_PARSER`.

## 4. Retrieval Architecture (v0.2)

```
User Query
  ↓ normalize_query (preserve STEM)
  ↓ classify_query → query_type + metadata_hint
  ↓ Candidate Retrieval (parallel)
       ├─ Semantic: TF-IDF/Dense cosine (or VectorStore.search)
       └─ Keyword: BM25-lite + phrase boost
  ↓ Score normalization (min-max per space)
  ↓ Weighted fusion (0.6/0.4 configurable)
  ↓ Metadata-aware soft boost (content_type/section, equation +0.35 etc.)
  ↓ Candidate fusion → ranked (30 candidates_before_rerank)
  ↓ Filter by min_relevance_score, MMR diversity pre-rerank
  ↓ Reranker (Simple or CrossEncoder) → Top 5-10
  ↓ MMR post-rerank → Final evidence
  ↓ Build SOURCE blocks → LLM
```

Weights normalized; ablation via evaluation determines optimality.

## 5. Reranking

Stage: 20–50 candidates → Reranker → Top 5–10.

- `SimpleReranker`: phrase 0.15 + overlap 0.1 + content_type/section boosts, now metadata-aware (equation 0.2, Results 0.08).
- `CrossEncoderReranker`: `sentence_transformers.CrossEncoder` scores query-doc pairs, `sigmoid` normalized, `0.4*base + 0.6*CE`. Falls back to simple, reports `simple(fallback)` if model unavailable. Config `RERANKER_PROVIDER=simple|CrossEncoder`.

## 6. Evidence Verification (v0.2)

Pipeline:

```
Answer
 ↓ extract_claims (sentence split, source/generated heuristics + claim_type)
 ↓ verify_numeric_claim (percent variants 14%/0.14/14 percent, tolerance 5%)
 ↓ verify_equation_claim (exact + variable-set lenient: P=VI ↔ P=V*I)
 ↓ verify_causal_claim (detect causes/leads to vs correlation in source; if source only correlation, mark unsupported with correction)
 ↓ evaluate_grounding (coverage uses strict verification for number/equation/causal)
 ↓ verify_citations_v2 (per citation VALID/PARTIAL/INVALID)
 ↓ detect_contradiction (efficiency/power values conflict across sources, e.g., 12% vs 18%)
```

Each claim stores: `claim_text, claim_type, evidence_ids, support_score, support_status, citation_status`.

Stricter for `number`, `equation`, `experimental_result`, `causal_claim`.

## 7. Citation Validation

For every citation verify: document exists in retrieved, page exists, section exists if provided, chunk exists, claim supported. States:

- `VALID` — doc+page+chunk found and claim supported
- `PARTIAL` — generic `[SOURCE]` without provenance or page missing
- `INVALID` — doc not in retrieved or unparsable

Metrics:

```
citation_accuracy = supported_citations / total_citations
citation_precision = valid / total_found
citation_recall = valid / retrieved_count
```

## 9. Metrics (v0.2)

- **Recall@5**: relevant retrieved / total relevant (relevance = page match or concept in text or chunk_id in relevant_chunks)
- **Precision@5**: relevant / 5
- **MRR**: mean reciprocal rank of first relevant
- **NDCG@5**: binary relevance DCG/IDCG
- **Citation Accuracy/Precision/Recall** (per citation VALID)
- **Groundedness** (weighted: retrieval 0.25, coverage 0.35, alignment 0.2, contradiction 0.1, quality 0.1 - penalty)
- **Unsupported Rate**
- **Answer Relevance** (query term overlap)

Measured on same demo_data (thermoelectric-paper.pdf 6p, notes, lab-manual, dataset) via `GET /api/evaluation/benchmark`:

| Precision@5 | 0.113 | **0.52** | **+0.407** |
| MRR | — (0) | **0.836** | +0.836 |

## 11. Error Analysis

See `docs/evaluation/error-analysis.md`. Summary:

- **2 partial cases** (Recall@5 0.667 and 0.333) not total failures; previously v0.1 had 2 total failures (Recall 0). No case with Recall@5=0 in v0.2.
- Types: `wrong_section` (efficiency query, page 1 notes ranked before page 4 results) and `reranker_failure`/`metadata_failure` (procedure query, page 3 at rank 3 not top-2). No `wrong_document`, `semantic_mismatch`, `chunking_failure`.

Trace example for procedure query shows `query_type=method`, `metadata_hint={section:Methods, content_type:procedure}`, `candidates_before_rerank 26 → final 5`, `reranker simple`, latency 45ms.

## 12. Limitations

- Dense embeddings require `sentence-transformers` + `torch` download (~120MB); offline install falls back to TF-IDF (still works, metrics above are TF-IDF based).
- CrossEncoder requires additional model; fallback to simple reranker logged as `simple(fallback)`.
- Table extraction heuristic (pipes / 2+ spaces) may miss complex scientific tables; figure detection only captions, no image understanding.
- Math validation via sympy cannot verify numeric correctness of empirical efficiency values, only syntax/dimensional.
- Answer relevance metric still term-overlap based, not semantic; hence drop not indicative of user-perceived quality.
- Evaluation total_relevant estimated (capped 3) may underestimate recall denominator.

## 13. Future Work

- VectorStore: Qdrant/PgVector with HNSW for scale (interface ready)
- Dense embeddings fine-tuned on STEM corpus
- OCR for scanned PDFs (Tesseract) + layout model (LayoutParser)
- Full MathJax rendering + sympy substitution with actual dataset values
- Human eval for explanation quality; add NDCG with graded relevance
- Expand evaluation to 50+ cases with human-labeled relevant_chunks
