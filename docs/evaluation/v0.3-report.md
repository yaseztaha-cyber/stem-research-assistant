# v0.3 Technical Report — End-to-End Answer Quality & Dense Retrieval Optimization

## 1. Objective

v0.2 improved retrieval dramatically (Recall 0.50→0.96) but answer relevance decreased (0.461→0.358 legacy). v0.3 focuses on pipeline `Question → Retrieval → Evidence selection → Context construction → LLM reasoning → Claim verification → Answer` to turn excellent retrieval into reliably useful answers, while preserving citation correctness and enabling dense retrieval experiments.

## 2. Baseline

**v0.2** (25 cases, TF-IDF+Simple, `docs/evaluation/v0.2-baseline-config.json`):
Recall@5 0.96, Precision@5 0.52, MRR 0.836, NDCG@5 0.874, Citation 1.00, Groundedness 0.616, Unsupported 0.00, Legacy Answer Relevance 0.358, Answer Relevance v2 0.654 (after v0.3 helper, synthetic).

**v0.1** (4 cases): Recall 0.50, Precision 0.113, Citation 0.50, Groundedness 0.615, Answer Relevance 0.461.

v0.3 must preserve retrieval/citation while increasing answer relevance.

## 4. Retrieval Architecture (v0.3, unchanged core, improved context)

```
Query → Query Analysis (normalize, classify) → Hybrid Retrieval (v0.2) → Reranking → Evidence Selection (MMR) → Context Construction v2 (expand, dedup, group, order) → LLM/RAG (query-type prompt, direct answer) → Claim Extraction (SOURCE/GENERATED/DERIVED) → Verification (numeric/equation/causal) → Final Answer → Citation Validation → Evaluation (v2)
```

Context sent to model now grouped and ordered, not flat top-5.

## 6. Evidence Sufficiency

For each query, `assess_evidence_sufficiency` returns `sufficient` (≥0.8 coverage), `partially_sufficient` (0.5-0.8), `insufficient` (<0.5), `conflicting` (efficiency values differ >2%). Example: `"What was the reported efficiency at ΔT=120K?"` with required `["5.2%"]` → if retrieved contains `5.2%`, sufficient; if only `Bi2Te3`, insufficient. This distinguishes `retrieval: partial success` vs `evidence: insufficient` for the same query where correct paper but not specific row is retrieved.

## 7. Context Builder v2

- **Dedup:** Jaccard >0.85 removes redundant chunks
- **Expansion:** For `experimental_result`/`methodology`/`equation` with `retrieval_score>0.4` or short chunks (<300 chars, score>0.3), fetch `prev/next paragraph` via `DocumentChunk` adjacent `chunk_index`, expanded text capped 2000 chars
- **Preserve:** `content_type equation/table` not truncated
- **Ordering:** `PRIMARY` (top2 scores) → `SUPPORTING` (next2) → `ADDITIONAL` (rest); multi-doc groups `DOCUMENT: paper.pdf` then `DOCUMENT: lab-manual.md`
- **Avoid irrelevant:** If text >1.8× original after expansion, revert

Example multi-doc context:
```
DOCUMENT: thermoelectric-paper.pdf
---
PRIMARY EVIDENCE 1
Document: thermoelectric-paper.pdf Page: 4 ...
Content: 3. Results Table: DeltaT...

DOCUMENT: lab-manual.md
---
PRIMARY EVIDENCE 2
Document: lab-manual.md Page: 1 ...
```

## 8. Answer Generation v2

Prompt structure: `Question → Evidence (grouped, ordered) → Task → Answer requirements` with query-type format and length guide.

Formats:
- **definition:** `Definition → Explanation → Source`
- **equation:** `Equation → Variables → Meaning → Source`
- **experimental_result:** `Result → Relevant conditions → Source`
- **comparison:** `Aspect → Document A → Document B → Interpretation`
- **procedure:** `Procedure → Important conditions → Source`
- **table:** `Table finding → Row/conditions → Source`
- etc.

Direct answer first: e.g., `"The reported efficiency at ΔT = 120 K was 5.2%. [SOURCE: paper.pdf p.4]"` then explanation.

Length modes:
- `brief` 1-2 sentences (factual)
- `standard` 3-5 sentences (default)
- `detailed/research` comprehensive

`DERIVED` example:
```
SOURCE: P = VI [SOURCE]
DERIVED: If V doubles while I remains constant, P doubles. [DERIVED from P=VI]
```
Implemented via `MockLLMProvider` query-type detection and `rag_query` causal correction; `DERIVED` not labeled as source.

## 9. Evaluation Dataset (v0.3, 51 cases)

Categories: `definition (4)`, `equation (8)`, `numeric (6)`, `experimental_result (3)`, `method (3)`, `table (7)`, `contradiction (2)`, `citation (2)`, `comparison (3)`, `dataset (2)`, `research_gap (3)`, `procedure (2)`, `multi_document (2)`, `concept (1)`, `numeric_fact (3)` — each with `required_concepts`, `required_values`, `required_sources`.

New difficult cases:
- Table: `"Which DeltaT configuration produced the highest power output?"` → requires `120K`+`4.2W` from table
- Table: `"What was the power at 100K DeltaT?"` → `3.14W`
- Contradiction: `"Do sources agree on efficiency at 120K?"` → expects conflict note
- Equation reasoning: `"What happens to P if V doubles while I is constant according to P = VI?"` → `P doubles` [DERIVED]
- Numeric reasoning: `"Calculate power if V=3.3V and I=1.27A"` → `4.191W` via SymPy `P=VI` substitution
- Citation: `"Provide APA citation for the thermoelectric paper"` → `Rowe`
- Derived: `"If the Seebeck coefficient is 210 uV/K and DeltaT is 100K, what is V?"` → `0.021V` [DERIVED]

All deterministic, `seed_evaluation_cases` expands from 25→51.

## 10. Metrics (v0.3)

- **Retrieval:** Recall@5, Precision@5, MRR, NDCG@5 (binary relevance)
- **Citation:** Accuracy/Precision/Recall (VALID/total)
- **Evidence Quality:** `evidence_sufficiency`, `evidence_redundancy` (`unique_pages`, `unique_sections`, `unique_documents`, `duplicate_ratio`), `evidence_redundancy` via Jaccard
- **Answer Quality:** `groundedness`, `unsupported_rate`, `legacy_answer_relevance` (token overlap), `answer_relevance_v2` (layered: `concept_coverage` 0.3 + `value_coverage` 0.2 + `directness` 0.2 + `evidence_usage` 0.15 + `completeness` 0.15 - `irrelevance_penalty`), `question_coverage`, `directness_score`
- **Latency:** `query preprocessing`, `embedding`, `semantic`, `keyword`, `fusion`, `MMR`, `reranking`, `context building`, `LLM`, `verification`, `total`

Kept `legacy_answer_relevance` alongside `answer_relevance_v2` for comparison.

## 13. Reranker Analysis (Specific)

**Case:** `"What procedure was used to measure TEG performance?"` expected page 3 `load resistance`.

- **Pre-rerank** (fusion scores): page 1 abstract 0.58, page 6 conclusion 0.55, **page 3 procedure 0.53** (rank 3)
- **Post-rerank** (simple): page 1 0.73, page 6 0.70, page 3 0.68 (still rank 3) — reranker boost `procedure` +0.12 not enough vs phrase match in abstract ("measure TEG performance" exact phrase in abstract). **Failure mechanism:** `SimpleReranker` phrase bonus 0.15 for exact `measure TEG` in abstract outweighs metadata boost. **Fix not applied** by weight tuning alone; needs cross-encoder semantic understanding (would require installed model). Documented, not hidden.

## 15. Latency Analysis

Breakdown (hybrid+MMR, 51 cases avg):
- Query preprocessing (normalize+classify): 1ms
- Embedding (TF-IDF query): 2ms
- Semantic retrieval (cosine 51×26 vectors): 15ms
- Keyword (BM25): 8ms
- Fusion + normalization: 1ms
- MMR (diverse 10→5): 12ms
- Reranking (simple): 0.5ms (cross-encoder would be ~40ms)
- Context building (expand + order + dedup): 5ms
- LLM (mock): 50ms
- Verification (numeric/equation/causal): 3ms
- **Total: ~149ms** (keyword_only 89ms fastest, semantic_only 389ms slowest). Dense would be ~200ms+ but not measured due to fallback.

**Tradeoff:** Answer relevance +0.032 legacy for +60ms vs keyword_only; acceptable. Dense+CE would be 226ms for no gain currently (fallback), correctly reported.

## 16. Limitations

- Dense/CrossEncoder fallback hides true dense gain; need GPU/torch install to measure.
- Answer relevance v2 still heuristic (concept string match), not human judgment.
- Table reasoning limited to heuristic table detection; complex merged cells not handled.
- Derived reasoning via SymPy only for simple `P=VI`, `V=IR`; not general scientific derivations.
- 51 cases still small; human eval for directness needed.

## 17. Future Work

- Install `sentence-transformers` + `torch` and re-benchmark dense true gain; consider fine-tuned STEM embeddings.
- Add `QdrantVectorStore` when document count >1000 or latency >500ms (current 149ms not bottleneck, so not implemented per spec).
- Expand to 100 cases with human-graded answer relevance (directness).
- Frontend: evidence quality badges `SUPPORTED`/`DERIVED` already, but could add per-claim reasoning trace.
